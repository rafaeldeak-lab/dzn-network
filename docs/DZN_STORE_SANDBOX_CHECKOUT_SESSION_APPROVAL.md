# DZN Store Sandbox Checkout Session Approval

## Status And Boundary

This slice adds the first DZN Store sandbox Checkout Session route, disabled by default:

- `functions/api/store/orders/[orderId]/checkout.ts`
- `functions/_lib/dzn-store-checkout.ts`
- `POST /api/store/orders/:orderId/checkout`

It can create a test-mode only Stripe Checkout Session after a pending local/test Store order already exists and belongs to the authenticated player. It updates only `store_orders` to `checkout_created`.

Required local/test gates:

- `DZN_STORE_SANDBOX_RUNTIME=local` or `test`
- `DZN_STORE_ENABLED=true`
- `DZN_STORE_CHECKOUT_ENABLED=true`
- `DZN_STORE_SANDBOX_CHECKOUT_ENABLED=true`
- `DZN_STORE_SANDBOX_CHECKOUT_SESSION_ENABLED=true`
- `DZN_STORE_LIVE_CHECKOUT_ENABLED=false`
- `DZN_LIVE_CHECKOUT_ENABLED` remains unset/false.
- `DZN_STORE_WEBHOOK_FULFILMENT_ENABLED=false`
- `DZN_SUPPORTER_CARDS_ENABLED=false`
- `DZN_EARNED_SPINS_ENABLED=false`
- `DZN_REWARD_WHEEL_ENABLED=false`
- `STRIPE_SECRET_KEY` must be a test-mode key beginning with `sk_test_`.

No Cloudflare variables, secrets, bindings, Pages config, or Workers config are added. These flags are read only from the current local/test runtime environment and remain absent from source-controlled Cloudflare config.

This slice creates no live payment path. The only external provider action it permits is a test-mode Stripe Checkout Session creation when every sandbox gate passes. It still does not add, create, mutate, or enable:

- No live Stripe Checkout Session.
- No Stripe Product, Price, Customer, PaymentIntent, refund, dispute, or webhook endpoint is created, updated, archived, or mutated by DZN.
- No Store webhook is processed.
- No `store_payment_events` row is written.
- No account entitlement is granted.
- No Supporter Card is issued.
- No earned spin is minted.
- No reward wheel runtime runs.
- No owner subscription, `/setup`, Nitrado, server-management, or server-ownership access is changed.
- No analytics, tracking, AI provider credentials, vector stores, metered model calls, Nitrado mutation, or Discord mutation are added.
- No production D1 write or remote migration apply is performed.
- No live checkout activation is performed.
- Issue #49 remains reserved for final live checkout activation.

- Owner subscription checkout at `functions/api/billing/create-checkout-session.ts` using `mode: "subscription"`.
- Owner subscription webhook handling at `functions/api/stripe/webhook.ts`.
- Canonical owner billing/readiness safety in `functions/_lib/plans.ts`.
- Store catalog safety helpers in `functions/_lib/dzn-store-catalog.ts`.
- Store sandbox pending order creation in `functions/_lib/dzn-store-orders.ts` and `functions/api/store/orders.ts`.
- Store catalog schema in `migrations/0071_dzn_store_catalog_admin_draft.sql`.
- Store order ledger schema in `migrations/0072_dzn_store_order_ledger_schema.sql`.

The Store sandbox checkout route is deliberately separate from owner billing. It does not call the owner entitlement layer and cannot satisfy the owner gate used by `/setup`, Nitrado linking, owner dashboards, owner onboarding, or server-management APIs.

## Runtime Contract

Canonical endpoint:

```text
POST /api/store/orders/:orderId/checkout
```

Request body:

```json
{
  "returnTo": "/store"
}
```

The route rejects client-supplied identity, owner, server, billing, entitlement, product, price, Stripe, quantity, amount, currency, livemode, status, success URL, or cancel URL fields.

The order id comes from the route parameter. The purchasing account comes from the existing Discord session model. A logged-out caller receives `401` and no D1 or Stripe access occurs.

## Order And Price Rules

Before Stripe is called, the route must resolve exactly one existing pending order server-side:

- `store_orders.id = :orderId`
- `store_orders.purchasing_user_id = current session user id`
- `store_orders.status = draft`
- `store_orders.livemode = 0`
- `store_orders.ledger_scope = local` or `sandbox`
- `store_orders.product_count = 1`
- `store_order_items.quantity = 1`
- Currency is `gbp`.
- Tax is `0` for this sandbox slice.
- Header and item totals match.
- The linked Store price is approved and active.
- The linked Store product/item remains account-bound, guaranteed-purchase, and no-competitive-advantage.
- Every paid-outcome flag remains `0`.
- The existing pending order has a valid `checkout_idempotency_key_hash`.
- The price uses a server-controlled `store_prices.stripe_price_id` with a bounded `price_...` id.

The request body cannot choose or override a Stripe Price id. The earlier order creation helper now allows a valid server-side `store_prices.stripe_price_id` so this approved checkout slice can use it, but that id is still catalog-owned, server-read, and not returned by the order route.

## Stripe Session Shape

The checkout helper sends:

```text
mode = payment
line_items[0][price] = server-controlled store_prices.stripe_price_id
line_items[0][quantity] = 1
client_reference_id = store_orders.id
success_url = safe DZN return URL with store_checkout=success and order id
cancel_url = safe DZN return URL with store_checkout=cancelled and order id
allow_promotion_codes = false
metadata[dzn_context] = dzn_store_sandbox
metadata[dzn_order_id] = store_orders.id
metadata[dzn_order_number] = store_orders.order_number
metadata[dzn_product_key] = store_order_items.product_key
metadata[dzn_ledger_scope] = store_orders.ledger_scope
payment_intent_data[metadata][dzn_context] = dzn_store_sandbox
payment_intent_data[metadata][dzn_order_id] = store_orders.id
payment_intent_data[metadata][dzn_product_key] = store_order_items.product_key
```

It uses a Stripe idempotency key derived from `store_orders.checkout_idempotency_key_hash`. The idempotency key must not contain email addresses, Discord ids, raw DZN user ids, names, customer ids, or private identifiers.

The helper rejects Stripe responses unless:

- `session.id` starts with `cs_test_`.
- `session.livemode === false`.
- `session.mode` is omitted/null or `payment`.
- `session.url` is present.

## Write Contract

When every guard passes and Stripe returns a safe test-mode session, the route updates only `store_orders`:

- `status = checkout_created`
- `stripe_checkout_session_id = cs_test_...`
- `stripe_payment_intent_id = pi_test_...` when Stripe returns one
- `stripe_customer_ref_hash = SHA-256 hash` when Stripe returns a customer id
- `checkout_session_expires_at = ISO timestamp` when Stripe returns expiry
- `store_flags_snapshot_json` records the sandbox gate state
- `updated_at = now`

The update is compare-and-set guarded by:

- same `id`
- same `purchasing_user_id`
- `status = draft`
- `livemode = 0`
- `stripe_checkout_session_id IS NULL`

If the order changes before the update, the route returns a conflict and performs no entitlement or fulfilment side effect.

## Response Contract

Successful response:

```json
{
  "ok": true,
  "order": {
    "status": "checkout_created",
    "livemode": false,
    "checkout": {
      "available": true,
      "url": "https://checkout.stripe.com/...",
      "session_id": null,
      "stripe_checkout_session_created": true,
      "livemode": false,
      "mode": "payment",
      "expires_at": "2026-08-27T15:00:00.000Z"
    }
  },
  "next_step": "redirect_to_test_mode_stripe_checkout"
}
```

The response must not expose:

- Raw Discord ids.
- Internal DZN user ids.
- Stripe customer ids.
- Checkout Session ids as a separate field.
- PaymentIntent ids.
- Webhook event ids.
- Tax internals beyond the zero-tax sandbox state.
- Private payment state.
- Card, CVC, bank, billing address, or payment method data.

The redirect URL itself is the browser redirect target from Stripe. No entitlement is granted from reaching the success URL.

## Tests And Acceptance Criteria

This slice is accepted only if tests prove:

- The route is disabled by default.
- Local/test runtime is required.
- Store, checkout, sandbox checkout, and checkout-session flags are required.
- `STRIPE_SECRET_KEY` must be a test-mode key beginning with `sk_test_`.
- Live checkout flags block before D1 or Stripe access.
- Webhook fulfilment, Supporter Card, earned-spin, and wheel flags must stay disabled.
- Logged-out callers receive `401`.
- Oversized or invalid JSON bodies are rejected.
- Request body identity/payment/product/price/owner/server fields are rejected.
- Cross-user and missing orders return `404`.
- Only owned pending draft orders can be checked out.
- Unsafe product/item/price/order rows block before Stripe.
- The Stripe call uses `mode=payment`, one server-controlled test Price id, one line item, safe URLs, no promotion codes, and non-sensitive metadata.
- The Stripe call uses an order-derived idempotency key.
- Non-test, live-mode, wrong-mode, or URL-less Stripe responses are rejected before D1 update.
- The route updates only `store_orders`.
- The route never writes `store_payment_events`, account entitlements, Supporter Cards, earned spins, spin ledgers, or wheel cooldowns.
- The response returns a Checkout redirect URL but no raw customer id, PaymentIntent id, Discord id, or separate Checkout Session id field.
- Cloudflare config files and `cloudflare-env.d.ts` are unchanged.
